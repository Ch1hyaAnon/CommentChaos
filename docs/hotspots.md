# 热点推荐与事件背景

## 本地运行

沿用 `.env.local` 中的 `DEEPSEEK_API_KEY`，密钥仅供服务端使用。运行前端 `npm run dev` 和后端 `node dev/node-local.mjs`，打开 http://127.0.0.1:5173。无需新增服务或数据库，不自动部署到远端。

热榜调用 60s 公共 API：`/v2/zhihu`、`/v2/weibo`、`/v2/bili`。公共实例有额度与连通性限制，B站或其他单源失败会显示降级，不使用导购 RSS 补位。AI 分类和评论使用现有 V4 Pro；正文读取、补检沿用 DeepSeek Search / Fetch。

## 数据流程

1. 并行抓取各平台，过滤明确促销、去重；关键词先筛完整候选池。
2. 对候选进行一次批量分类，仅接受已有 ID。按社区直接相关程度、讨论空间、跨平台出现情况和平台排名排序。最多10条，每平台最多3条；目前三平台实际最多9条。允许少于上限或为空。
3. 开楼传入所选 `hotspot_id`。服务端从候选索引取可信链接；客户端不能指定待抓取 URL 或伪造正文。
4. 优先读取知乎原页面，微博/B站搜索页则检索同一事件报道。正文链接检查 HTTPS、公网 DNS 和可见重定向，失败时保留合法摘要。DNS 检查使用 Node/Deno 内置 `node:dns/promises`。
5. 联合评估校验同一事件锚点；只与话题相似的其他经历、历史事件不进入背景。原文证据必须连续出现在所保留摘录中，标题本身和重复证据不计数。
6. 至少两个具体信息点才开楼。原文中的指控、观点、未确认信息分别标记，不能作为确定事实。用户补充仅帮助检索，并在生成数据中单独标记为未核实。
7. 简报和证据作为独立数据注入。首轮要求至少4条评论涉及至少两个信息点；不限制所有短评都复述事实，继续允许接话、反串、表情与阴阳怪气。

热点评论生成后再独立执行一次事实复核，修正材料外的具体事实、检查首轮至少4条涉及至少两个信息点，并同步更新总结。只改正文与总结，保留角色、立场、回复结构和直接语气；复核失败返回 `hotspot_generation_ungrounded`，不展示未通过的评论。复核使用温度0、最多1800 tokens、15秒上限。

内容与现有事实/梗检索共享约25秒预算，检索阶段最多5次模型调用。检索完成后另行执行评论生成，评论生成与事实复核不计入这25秒，整体请求时间会更长。最多3个背景来源，摘录合计不超过4000字。模型的语义判断与评论质量仍需人工评估，结构测试不等于内容质量保证。

## 接口兼容与状态

- `GET /functions/v1/app/trending?q=关键词&community=game`：保留原字段，增加 `id/platform/description/rank/heat/fetched_at/appearances`；返回 `sources/degraded/stale/fetched_at`。全部失败或无相关结果也正常返回空列表及来源状态。
- `POST /functions/v1/app/generate`：新增可选 `hotspot_id/hotspot_token/hotspot_supplement`；未选热点时沿用原流程。`news_context` 仍只是未核实线索。
- 成功响应新增 `hotspot_context`（状态、原文信息点、来源和获取时间）与 `hotspot_token`，保留评论 JSON、导演指令和其他检索字段。
- `422 hotspot_content_insufficient`：事件细节不足，暂停生成，保留输入，可补充线索、刷新热点或取消选择。
- `410 hotspot_expired`：候选或会话背景失效，保留输入，需刷新并重新选择。已有楼可以重新开楼，不能悄悄替换本楼背景。
- 前端分别显示抓取时间和已知发布时间；`summary_only` 表示只有摘要，不冒充正文。

热榜原始结果缓存10分钟；分类正常时同样缓存10分钟，分类失败/空结果/旧缓存降级时最多缓存1分钟后重试。全部来源失败时可用距抓取不超过30分钟的旧结果。候选索引最多500条；分类缓存、检索缓存、会话快照分别最多100条，合并同进程内并发请求。

正文/检索背景缓存30分钟。开楼成功后创建独立30分钟快照，续楼使用返回的 token，不重新检索改变事件背景。重开楼清除前端 token、来源和简报；重启服务会清空进程缓存。

## 验证与诊断

- `npm test`：包括热榜异常、广告、社区匹配、证据校验、正文/摘要降级、同话题不同事件、缓存和续楼快照。
- `npm run check:function:node`：服务端类型检查；`npm run build`：前端类型检查与构建。
- `node --env-file=.env.local dev/audit-hotspots.mjs`：游戏、职场、情感各取最多两条真实热点，执行真实链路。`--lists` 仅检查推荐。外部榜单不足时不会编造案例补位。
- 本地真实联调记录保存到 gitignored 的 `artifacts/hotspots/`，含公开测试条目的请求、可见响应、阶段、耗时和生成结果，移除密钥。此脚本只用于明确的公开话题测试，不应用于私人吐槽。
- 浏览器检查脚本为 `dev/check-hotspot-ui.mjs`，需本机可用 Chrome 和外部安装的 Playwright；通过 `PLAYWRIGHT_MODULE` 指定其模块路径，应用运行不依赖 Playwright。

生产日志仅记追踪编号、阶段、分类计数、耗时与降级原因。完整请求只在显式本地审计中保存。公共实例故障不代表原平台没有热点，空结果也不代表事件不存在。

## 回滚

恢复此次热点相关代码到修改前的版本，再重启本地后端并刷新前端；没有数据库迁移或远端发布需要回滚。现有梗库、周更流程和普通自由输入接口不受影响。
